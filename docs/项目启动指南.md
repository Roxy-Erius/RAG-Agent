## 1. 项目简介

本项目是一个基于 RAG（检索增强生成）技术的多模态电商智能导购 AI Agent，用自然语言对话帮助用户发现、比较和购买商品。

**核心流程：** 用户发起对话 -> 后端向量检索 ChromaDB 获取相关商品 -> 组装上下文注入 LLM System Prompt -> 豆包大模型生成推荐回复 -> SSE 流式推送到 Android 客户端。

**关键特性：**
- 语义级商品检索（文本 + 图片多模态 embedding）
- 双向量存储：文本向量 + 图片向量，支持跨模态检索和加权融合
- SSE 流式对话，结构化 JSON 事件（文本 token / 商品卡片 / 加购 / 完成）
- 防幻觉后处理，自动过滤 LLM 编造的不存在商品
- 用户认证（JWT）、会话持久化、购物车管理

## 5. 配置文件的准备

项目中有 **两个需要手动创建的配置文件**，它们已被 `.gitignore` 排除，不会随代码提交。

### 5.1 后端配置：`application.yml`

**Step 1：复制模板**

```bash
# 在项目根目录执行
cp server/src/main/resources/application.yml.example server/src/main/resources/application.yml
```

**Step 2：编辑 `server/src/main/resources/application.yml`**

模板内容及需要填写的字段说明如下：

```yaml
server:
  port: 8080

spring:
  application:
    name: rag-server
  datasource:
    url: jdbc:mysql://服务器IP:3306/rag_agent?useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai
    username: rag_agent              # 数据库用户名
    password: 你的MySQL密码            # <-- 替换为实际密码
    driver-class-name: com.mysql.cj.jdbc.Driver

# ==================== ChromaDB 配置 ====================
chromadb:
  url: http://服务器IP:8000              # ChromaDB 服务地址
  collection-name: products

# ==================== 火山引擎 API 配置 ====================
volcengine:
  base-url: https://ark.cn-beijing.volces.com/api/v3
  # Chat 模型（对话生成）
  chat:
    api-key: 你的chat模型API_KEY        # <-- 替换为实际 API Key
    model-id: 你的chat模型endpoint-id   # <-- 替换为实际的 Endpoint ID
  # Embedding 模型（向量化）
  embedding:
    api-key: 你的embedding模型API_KEY   # <-- 替换为实际 API Key
    model: doubao-embedding-vision-251215

# ==================== RAG 参数 ====================
rag:
  top-k: 3                             # 检索返回 Top-K 条商品
  similarity-threshold: 0.5            # 相似度阈值（0~1）
  max-context-messages: 10             # 多轮对话最大上下文消息数

# ==================== 数据集路径 ====================
dataset:
  path: ../ecommerce_agent_dataset     # 相对于 server/ 的路径
```

> **如何获取 API Key：** 登录[火山引擎控制台](https://console.volcengine.com/ark/)，在「在线推理」中创建推理接入点，复制对应的 API Key 和 Endpoint ID。需要分别创建 **Chat 模型** 和 **Embedding 模型** 两个接入点。

### 5.2 前端配置：`local.properties`

该文件在 `client/` 目录下，Android 项目首次用 Android Studio 打开时会自动生成。如果你是通过命令行构建，需要手动创建。

**文件路径：** `client/local.properties`

**内容：**

```properties
# SDK 路径（根据你的实际安装位置修改）
sdk.dir=D\:\\Android\\Sdk

# 后端地址（不提交到 Git，每人自己配）
# 模拟器用 http://10.0.2.2:8080，真机 USB 调试用局域网 IP
base.url=http://10.0.2.2:8080
```

**关于 `base.url` 的说明：**

| 场景 | base.url 值 | 说明 |
|------|-------------|------|
| Android 模拟器（AVD） | `http://10.0.2.2:8080` | `10.0.2.2` 是模拟器到宿主机 localhost 的映射 |
| 真机 USB 调试 | `http://192.168.x.x:8080` | 使用电脑的局域网 IP 地址 |
| 远端服务器 | `http://159.75.105.25:8080` | 如果后端部署在远程服务器 |

> **获取局域网 IP（Windows）：** `ipconfig` -> 找到「IPv4 地址」，格式如 `192.168.1.100`。

## 6. 远程服务说明（MySQL / ChromaDB）

本项目使用**远程服务器**上的 MySQL 和 ChromaDB，开发者不需要在本地安装 Docker 或启动数据库服务。

| 服务 | 地址 | 端口 | 说明 |
|------|------|------|------|
| MySQL | `159.75.105.25` | `3306` | 数据库名：`rag_agent` |
| ChromaDB | `159.75.105.25` | `8000` | HTTP API v2 |

> **网络要求：** 需要能够访问该服务器。如果在公司内网或需要 VPN 才能访问，请提前确认网络连通性。

### 6.1 验证网络连通性

```bash
# 测试 MySQL 端口（Windows PowerShell / cmd）
telnet 159.75.105.25 3306

# 测试 ChromaDB 端口
telnet 159.75.105.25 8000

# 或使用 curl 测试 ChromaDB HTTP API
curl http://159.75.105.25:8000/api/v2/heartbeat
```

### 6.2 数据库初始化

服务器上的 MySQL 实例已经创建了 `rag_agent` 数据库。如果需要重新初始化数据库表结构，可以执行：

```bash
# 在项目根目录，使用 MySQL 客户端连接远程服务器执行初始化脚本
mysql -h 159.75.105.25 -P 3306 -u rag_agent -p < data/init.sql
```

> **注意：** `data/init.sql` 包含 `DROP TABLE IF EXISTS` 语句，只在首次搭建或需要重建时执行。日常开发中，项目启动时会自动创建以下表：
> - `conversations` — 会话表（`ConversationRepository.@PostConstruct` 自动创建）
> - `messages` — 消息表（同上）
>
> 如果 `cart_items` 表或 `users` 表不存在，启动时会在首次访问时报错。建议执行一次 `init.sql` 创建完整的表结构。

## 7. 后端启动

### 7.1 编译项目

```bash
# 在项目根目录执行
# Windows（Git Bash）
D:/apache-maven-3.9.9/bin/mvn compile -f "d:/-\RAG-Agent/server/pom.xml"

# 或者使用 Maven Wrapper
cd server
mvnw compile
```

### 7.2 安装依赖

首次启动前建议先安装所有依赖到本地仓库：

```bash
D:/apache-maven-3.9.9/bin/mvn install -f "d:/-\RAG-Agent/server/pom.xml" -DskipTests
```

> **国内加速：** 如果下载依赖缓慢，请在 Maven 配置文件 `~/.m2/settings.xml`（Windows 上为 `C:\Users\<用户名>\.m2\settings.xml`）中添加阿里云镜像：
>
> ```xml
> <mirrors>
>   <mirror>
>     <id>aliyun</id>
>     <mirrorOf>central</mirrorOf>
>     <name>Aliyun Maven Mirror</name>
>     <url>https://maven.aliyun.com/repository/public</url>
>   </mirror>
> </mirrors>
> ```

### 7.3 启动服务

```bash
# Windows（Git Bash）
D:/apache-maven-3.9.9/bin/mvn spring-boot:run -f "d:/-\RAG-Agent/server/pom.xml"

# 或者进入 server 目录后使用 Maven Wrapper
cd server
mvnw spring-boot:run
```

**启动日志关键信息：**

```
# 成功标志
Started RagServerApplication in X.XXX seconds

# 数据导入（如果有数据集目录）
数据导入完成！共导入 XXX 条商品

# 向量索引（首次运行）
开始向量索引，共 XXX 条商品（首次运行，需调用 Embedding API）
向量索引完成! 文本 XXX 条, 图片 XXX 条

# 后续启动（跳过索引）
ChromaDB products_text 已有数据，跳过索引（缓存命中，零 API 调用）
```

### 7.4 启动流程详解

项目启动后按以下顺序执行（`CommandLineRunner`）：

1. **`DataImportService`（`@Order(0)`）**：检查 `products` 表是否有数据。没有则扫描 `ecommerce_agent_dataset/` 目录，将 JSON 商品数据导入 MySQL。
2. **`KnowledgeIndexer`（`@Order(1)`）**：检查 ChromaDB 的 `products_text` 集合是否已有数据。没有则将 MySQL 商品数据向量化（调用 Embedding API）并写入 ChromaDB。**首次运行会消耗 Embedding API 额度，后续启动自动跳过。**

## 8. 前端启动

### 8.1 用 Android Studio 打开项目

1. 启动 Android Studio
2. File -> Open -> 选择 `client/` 目录（不是项目根目录）
3. 等待 Gradle 同步完成（首次同步需要下载依赖，请保持网络畅通）

### 8.2 Gradle 配置说明

`client/gradle.properties` 已配置关键参数（无需手动修改）：

```properties
org.gradle.jvmargs=-Xmx2048m -Dfile.encoding=UTF-8
android.useAndroidX=true
kotlin.code.style=official
android.nonTransitiveRClass=true
```

Gradle Wrapper 已包含在项目中（`client/gradlew`），无需安装系统级 Gradle。

### 8.3 创建 Android 模拟器

1. Android Studio -> Device Manager -> Create Device
2. 选择 **Pixel 6**（或任意 Phone 设备）
3. 系统镜像选择 **API 36**（Android 15，VanillaIceCream）
4. 完成创建并启动模拟器

> **为什么选 API 36？** AGP 9.0.1 要求 `compileSdk = 36` 且 `targetSdk = 36`，模拟器需要至少 API 36 系统镜像才能完整测试。

### 8.4 真机 USB 调试（可选）

1. 手机开启「开发者选项」和「USB 调试」
2. USB 连接电脑
3. 修改 `client/local.properties` 中的 `base.url` 为电脑局域网 IP
4. 在 Android Studio 顶部设备列表中选择你的手机
5. 确保手机和电脑在同一 Wi-Fi 网络下

### 8.5 运行 App

**方式一：Android Studio（推荐）**

- 点击工具栏的绿色 Run 按钮（或 Shift + F10）
- 选择目标设备（模拟器或真机）

## 10. 故障排查

### 10.1 Maven 依赖下载失败

**症状：** `mvn compile` 报 `Could not resolve dependencies`

**解决方案：**
1. 确认网络可以访问 Maven Central
2. 配置阿里云 Maven 镜像（见 [7.2 节](#72-安装依赖)）
3. 删除本地缓存重试：`rm -rf ~/.m2/repository` 后重新 `mvn install`

### 10.2 数据库连接失败

**症状：**
```
Communications link failure
The last packet sent successfully to the server was 0 milliseconds ago
```

**解决方案：**
1. 确认能 ping 通远程服务器：`ping 159.75.105.25`
2. 确认 MySQL 端口可达：`telnet 159.75.105.25 3306`（Windows 需启用 Telnet 客户端功能）
3. 检查 `application.yml` 中的数据库密码是否正确
4. 确认服务器防火墙已开放 3306 端口

### 10.3 ChromaDB 连接失败

**症状：**
```
java.net.ConnectException: Connection refused
```
或日志中 `KnowledgeIndexer` 无法创建 Collection

**解决方案：**
1. 确认 ChromaDB 服务在远程服务器上正常运行
2. 验证 HTTP 可达：`curl http://159.75.105.25:8000/api/v2/heartbeat`
3. 检查 `application.yml` 中 `chromadb.url` 配置是否正确

### 10.4 火山引擎 API 调用失败

**症状：** 日志中出现 `AuthFailure` 或 `InvalidApiKey` 或 `401 Unauthorized`

**解决方案：**
1. 登录火山引擎控制台，确认 API Key 未过期
2. 确认 Endpoint ID 属于正确的模型接入点
3. 确认账户余额充足（火山引擎按量付费）
4. Chat 模型和 Embedding 模型需要**分别创建**接入点，各有独立的 API Key

### 10.5 Embedding API 调用失败（索引阶段）

**症状：**
```
Embedding API 返回 401: {"error":{"code":"InvalidApiKey"...}}
```
或连续 3 次失败后索引终止

**解决方案：**
1. 确认 `volcengine.embedding.api-key` 已填写正确的 Embedding 模型 API Key（不是 Chat 模型的 Key）
2. 确认 Embedding 模型的 Endpoint ID 正确
3. 如果不需要 Embedding 功能，可以暂时删除 ChromaDB 的两个 Collection，后端会优雅降级（检索返回空结果）

### 10.6 Android Gradle Sync 失败

**症状：** `Could not resolve all dependencies` / `Could not find com.android.tools.build:gradle:9.0.1`

**解决方案：**
1. 确认 Android Studio 版本 >= Meerkat (2024.3.1)
2. 在 `settings.gradle.kts` 中确认 `google()` 仓库存在
3. 如在国内，需要在 `settings.gradle.kts` 中的 `dependencyResolutionManagement` 里添加国内镜像：
   ```kotlin
   repositories {
       maven { url = uri("https://maven.aliyun.com/repository/public") }
       maven { url = uri("https://maven.aliyun.com/repository/google") }
       google()
       mavenCentral()
   }
   ```

### 10.7 App 无法连接后端

**症状：** App 提示网络错误 / 请求超时

**解决方案：**
1. **模拟器场景：** 确认 `local.properties` 中 `base.url=http://10.0.2.2:8080`（不能是 `localhost`）
2. **真机场景：** 确认 `base.url` 使用的是电脑局域网 IP（如 `http://192.168.1.100:8080`）
3. 确认后端服务正在运行且端口为 8080
4. 确认防火墙允许 8080 端口入站连接（Windows 防火墙可能阻止）

### 10.8 Bash on Windows 路径问题

**症状：** `bash: cd: -RAG-Agent: invalid option` 或路径以 `-` 开头导致命令解析错误

**解决方案：**
1. 使用 `./-RAG-Agent` 或绝对路径 `d:/-\RAG-Agent` 来消除歧义
2. 或将仓库克隆到不含 `-` 开头的目录名
3. ADB 命令建议在 `cmd` 中执行，或使用 `cmd //c "命令"` 包裹

### 10.9 AGP 版本兼容问题

**症状：** `compileSdkVersion 36 requires compileSdk 36` 等 SDK 版本相关错误

**解决方案：**
1. 在 Android Studio 的 SDK Manager 中安装 Android SDK Platform 36
2. 在 SDK Tools 标签页中安装 Android SDK Build-Tools 36.1.0
3. 确认 `build.gradle.kts` 中 `compileSdk = 36` 和 `targetSdk = 36`
