## 一、项目总览

### 1.1 课题背景

利用 AI Agent + RAG 技术，构建多模态电商智能导购助手，将传统"展示型广告"升级为"交互型导购"，实现从内容浏览到购买决策的深度连接。

### 1.2 评审权重与合格线

| 维度 | 权重 | 关键词 |
|------|------|--------|
| **基础功能完整性** | 35% | 端到端链路跑通：Android 对话 → 后端 RAG → 模型生成 → 流式返回 → 商品卡片 |
| **工程质量** | 25% | 代码结构清晰、接口设计合理、错误处理完善、文档齐全 |
| **效果与可靠性** | 20% | 检索准确率、无幻觉输出、多轮对话流畅 |
| **加分项深度** | 20% | 选做但要有深度，做精一项胜过浅尝三项 |

**合格线（必须全部达到）：**
- Android 原生 App（不接受纯 Web）
- 对话窗口，支持发送文字
- 接收并渲染 AI 流式回复（SSE）
- 回复中包含可点击商品卡片
- 后端集成向量数据库，实现 RAG 基本链路
- 理解模糊需求 → 检索商品 → 给出推荐理由 → 不编造虚假信息

### 1.3 加分项策略

| 优先级 | 方向 | 难度 | 理由 |
|--------|------|------|------|
| **首选** | 多轮上下文记忆 + 反选排除 | ⭐~⭐⭐ | RAG 项目核心能力展示，纯后端即可实现 |
| **次选** | 购物车与下单流程 | ⭐~⭐⭐ | Java 后端同学最顺手，体现业务闭环 |
| **可选** | 拍照找货（多模态） | ⭐⭐⭐ | 有 VLM API 可用，优先级低于前两项 |

### 2.3 核心数据流

**链路一：知识库构建（离线，启动时执行）**

```
MySQL 读取 100 条商品
  → 拼接文本："{title} {category} {brand} {base_price}元 {marketing_description}"
  → 调用 Doubao-embedding-vision API 获取向量
  → 存入 ChromaDB，附加 productId 为 Metadata
```

**链路二：用户问答（实时）**

```
Android 发起 SSE 请求，携带用户问题 + sessionId
  → LangChain4j AiServices 自动执行：
     1. 用户消息 Embedding → 向量检索 Top-3 商品
     2. 注入 ChatMemory 历史对话
     3. 组装 System Prompt + 检索上下文 + 用户消息
     4. 调用 Doubao-Seed-2.0-lite 流式生成
  → 通过 SseEmitter 逐 Token 推送给 Android
  → Android 解析 [PRODUCT:id] 标记，渲染商品卡片
```

### 2.4 接口设计

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 流式对话 | GET | `/api/chat/stream?message={msg}&sessionId={id}` | SSE 流式返回 |
| 同步对话（调试用） | POST | `/api/chat/sync` | 同步返回完整结果 |
| 商品详情 | GET | `/api/products/{id}` | 单个商品信息 |
| 商品批量查询 | GET | `/api/products/batch?ids=1,2,3` | 批量商品信息 |
| 知识库重导 | POST | `/api/admin/reimport` | 重新构建向量索引 |
| 健康检查 | GET | `/api/health` | 服务状态 |

### 2.5 SSE 消息格式约定

```jsonc
// 普通文本 Token（逐字推送）
{"type": "token", "content": "推荐"}

// 商品卡片触发（流式过程中嵌入）
{"type": "product", "productId": "p_beauty_001"}

// 流结束标记
{"type": "done"}

// 错误
{"type": "error", "message": "服务暂时不可用"}
```

### 2.6 Prompt 工程规格

**System Prompt 模板：**

```
你是一个专业的电商导购助手。你的职责是根据用户需求，从商品库中推荐合适的商品。

## 严格规则
1. 你只能推荐下方【商品库】中列出的商品，绝对不能推荐不存在的商品
2. 你不能编造商品的价格、规格、优惠信息等任何参数
3. 如果商品库中没有匹配的商品，请如实告知用户，不要编造
4. 推荐时请给出具体理由，结合商品的实际特点
5. 回复要简洁专业，适合移动端阅读，控制在200字以内
6. 当用户需求模糊时，主动提问引导用户细化需求

## 输出格式
- 正常回复使用纯文本
- 当推荐具体商品时，在商品描述后插入标记：[PRODUCT:id]
  例如：这款洗面奶非常适合油皮使用 [PRODUCT:p_beauty_001]，价格也很实惠。

## 商品库
{context}
```

**防幻觉策略（三层防护）：**

1. **Prompt 级硬约束** — System Prompt 明确禁止编造不存在的商品
2. **检索级过滤** — 只注入 Top-K 检索结果，相似度过低的商品不注入
3. **后处理校验** — 检查返回内容中的 `[PRODUCT:id]` 标记，验证 ID 是否存在于检索结果中；无匹配时直接返回兜底话术，不调用 LLM

### LangChain4j 核心装配规格

```java
// LangChain4jConfig.java 中需要装配的 Bean：

@Bean
EmbeddingModel embeddingModel()          // Doubao 或 all-MiniLM-L6-v2

@Bean
EmbeddingStore<TextSegment> embeddingStore()  // ChromaDB 连接

@Bean
ContentRetriever contentRetriever()      // maxResults=3, minScore=0.5

@Bean
StreamingChatLanguageModel chatModel()   // Doubao-Seed-2.0-lite

// ShoppingAssistant.java 接口定义：
@SystemMessage("你是电商导购助手...")    // 完整 Prompt 见 2.6 节
interface ShoppingAssistant {
    String chat(@MemoryId String sessionId, @UserMessage String message);
}

// RagService.java 中构建 Agent：
AiServices.builder(ShoppingAssistant.class)
    .streamingChatLanguageModel(chatModel)
    .contentRetriever(contentRetriever)
    .chatMemoryProvider(id -> MessageWindowChatMemory.withMaxMessages(10))
    .build();
```

## 附录 C：完整建表 SQL

```sql
USE rag_agent;

-- 商品主表
CREATE TABLE products (
    product_id VARCHAR(50) PRIMARY KEY COMMENT '商品ID',
    title VARCHAR(300) NOT NULL COMMENT '商品标题',
    brand VARCHAR(100) NOT NULL COMMENT '品牌',
    category VARCHAR(50) NOT NULL COMMENT '类目',
    sub_category VARCHAR(50) NOT NULL COMMENT '子类目',
    base_price DECIMAL(10,2) NOT NULL COMMENT '基础价格',
    image_path VARCHAR(200) DEFAULT '' COMMENT '图片相对路径',
    marketing_description TEXT COMMENT '营销描述',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商品信息表';

-- SKU 表
CREATE TABLE product_skus (
    sku_id VARCHAR(50) PRIMARY KEY COMMENT 'SKU ID',
    product_id VARCHAR(50) NOT NULL COMMENT '所属商品ID',
    properties JSON COMMENT 'SKU 属性 JSON',
    price DECIMAL(10,2) NOT NULL COMMENT 'SKU 价格',
    FOREIGN KEY (product_id) REFERENCES products(product_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商品SKU表';

-- FAQ 表
CREATE TABLE product_faqs (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    product_id VARCHAR(50) NOT NULL,
    question VARCHAR(500) NOT NULL,
    answer TEXT NOT NULL,
    FOREIGN KEY (product_id) REFERENCES products(product_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商品FAQ表';

-- 用户评论表
CREATE TABLE product_reviews (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    product_id VARCHAR(50) NOT NULL,
    nickname VARCHAR(50) NOT NULL,
    rating INT NOT NULL,
    content TEXT NOT NULL,
    FOREIGN KEY (product_id) REFERENCES products(product_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户评论表';

-- 购物车表（加分项）
CREATE TABLE cart_items (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    session_id VARCHAR(50) NOT NULL,
    product_id VARCHAR(50) NOT NULL,
    quantity INT DEFAULT 1,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (product_id) REFERENCES products(product_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='购物车表';

-- 索引
CREATE INDEX idx_category ON products(category);
CREATE INDEX idx_sub_category ON products(sub_category);
CREATE INDEX idx_brand ON products(brand);
CREATE INDEX idx_base_price ON products(base_price);
```

| 5 | 模拟器连不上后端 | 网络隔离 | 用 `10.0.2.2:8080` 替代 `localhost` |
| 6 | Doubao API 401 | API Key 错误 | 检查完整 Key 和 Model ID |
| 7 | SSE 连接立即断开 | 端口占用或后端未启动 | `netstat -ano \| findstr 8080` 排查 |
| 8 | RecyclerView 不刷新 | notify 在子线程 | `runOnUiThread { adapter.notify...() }` |
| 9 | 商品卡片点击无响应 | 焦点被拦截 | 设置 `android:clickable="true"` |
| 10 | ChromaDB "Collection not found" | 初始化失败 | 调用 `POST /api/admin/reimport` |
| 11 | Gradle sync 超时 | 首次下载慢 | 配镜像 + 等待 10-20 分钟 |
| 12 | ChromaDB 初始化静默失败 | 异常被吞 | 检查控制台日志，确认 Docker 运行 |
