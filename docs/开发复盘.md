## 0. 项目背景

把现有 **Java 后端 RAG 问答系统** 升级成 **「类天猫的 Agent 导购前端」**：
- 后端已有：RAG 检索、LLM 对话（SSE 流式）、购物车、商品/订单/评价/FAQ 接口
- 目标前端：`web/` 目录下的 React 应用，包含对话区 + 商品卡片 + 购物车抽屉 + 订单页
- 核心交互：SSE 流式回复里嵌入 `data-card` 商品卡片，用户可「加入购物车」→ 结算 → 订单

## 1. 现有后端结构（已摸清）

```
server/src/main/java/com/ragagent/
├── controller/
│   ├── ChatController.java      # POST /api/chat/stream (SSE), /api/chat, /api/chat/reset
│   ├── ProductController.java   # GET /api/products/{id}, /batch, /search, /{id}/skus|reviews|faqs
│   ├── CartController.java      # GET /api/cart, POST /add, DELETE /remove, PATCH /update
│   ├── OrderController.java     # POST /checkout
│   └── HealthCheckController.java
├── service/  (ChatService, CartService, RetrieverService, EmbeddingService, ImageService...)
├── repository/  (Jdbc... ProductRepository, CartRepository, OrderRepository[新建])
├── model/    (Product, CartItem, Order[新建], OrderItem[未用])
├── security/ JwtAuthFilter.java  # 从 Authorization 头解析 userId，无 token 时匿名
└── config/   WebConfig.java (静态资源 + CORS[新增])
```

**鉴权模型**：`JwtAuthFilter.getUserId(request)` 返回 `Long` 或 `null`。
- `null` → 匿名，用 `sessionId` 关联购物车/订单
- 非 null → 登录用户，按 `userId` 关联
- 前端目前**不强制登录** → 默认匿名走 `sessionId`

## 3. 已知问题 / 坑（交接必读）

### 3.0 ⚠️ embedding 从未切到 Qwen（澄清用户记忆）
`application.yml` 里：
- `volcengine.chat.base-url` → **Qwen**（`dashscope.aliyuncs.com`，`qwen-max`）✅ 聊天是 Qwen
- `embedding.base-url` → **仍是本地 Chinese-CLIP 代理 `http://localhost:8001`** ❌ 没切 Qwen
  即「embedding 改 Qwen」这件事**实际没做**，配置还是本地 Python 多模态 embedding 服务。

### 3.1 SSE 500 的两层根因（已定位）
**第一层（已修复）**：`EmbeddingService.buildPost` 用
`BodyPublishers.ofString(jsonBody)` 未指定编码，Windows 默认 GBK，
中文字段把 JSON 弄坏 → 本地代理收 `{"text":""}` 返回 400 `text is required`。
→ **修复**：`EmbeddingService.java` 改为 `ofString(jsonBody, StandardCharsets.UTF_8)`，
重新编译后 embedding 正常（已验证本地代理返回 512 维向量）。

**第二层（已解决，切 DeepSeek）**：修复 embedding 后 SSE 仍 500，根因是新报
`LLM 调用失败: code=Arrearage / overdue-payment`（原 qwen-max 阿里云账号**欠费被封**）。
→ **解决**：`application.yml` 的 `volcengine.chat` 从 Qwen 换成 **DeepSeek**：
   `base-url=https://api.deepseek.com/v1`，`model-id=deepseek-chat`，填新 key。
→ **验证**：SSE 已通，DeepSeek 流式回复 + `done` 事件正常，无 500。
→ 备注：DeepSeek 无 Flash/Pro 之分，`deepseek-chat`(V3)/`deepseek-reasoner`(R1) 共用一把 key。

### 3.2 其他
- **商品字段名**：前端用 `title` 不是 `name`；价格 `basePrice`(Double)。
- **中文乱码**：仅 PowerShell 控制台显示问题，HTTP 响应是 UTF-8，前端 fetch 正常。
- **端口**：后端 8080，Python embedding 代理 8001。前端 dev 用 5173。

- **env**：`web/.env.development`（`VITE_API_BASE=/api`）；`web/vite.config.ts` 配 `/api` → `http://localhost:8080` proxy

### 4.1 SSE 协议（已确认，来自 `ChatService.flushSseBuffer`）
后端用 Spring `SseEmitter.event().data(jsonString)` 发送，**每个 `data:` 行是一段 JSON**，
前端按 `event-stream` 解析：`\n\n` 分隔，`data: ` 前缀去掉后 `JSON.parse`。

| type | 字段 | 前端动作 |
|------|------|---------|
| `token` | `content:string` | 追加到当前消息正文 |
| `product` | `productId:string` | 拉 `GET /api/products/{id}`（已带 images）渲染一张卡片，挂到当前消息 |
| `add_to_cart` | `productId,quantity,int,mode:"add"\|"set",skuLabel?:string` | 调 `POST /api/cart/add`（或乐观更新 Zustand） |
| `delete_from_cart` | `cartItemId:int` | 调 `DELETE /api/cart/remove` |
| `clear_cart` | — | 清空购物车 |
| `done` | — | 结束本轮，关闭加载态 |

> 注意：`product` 事件只给 `productId`，前端需再请求详情接口取图/标题/价格。
> LLM 文本里用 `[PRODUCT:id]` / `[ADD_TO_CART:id:qty:skuLabel]` / `[DELETE_FROM_CART:id]` / `[CLEAR_CART]`
> 标签驱动，后端已做 ID 纠错与未完成标签缓冲。

### 4.2 组件草图
- `App.tsx`：路由 + 布局（顶部导航 + 购物车图标）

## 7. 召回率优化（多模态检索）

### 7.1 背景问题
原召回评测 Hit@1=29.41%、Hit@10=58.82%、MRR=0.3549，看似很低。

### 7.2 发现：评测集本身是脏的
`RetrievalEvaluationTest.java` 的 ground truth 大量错误：
- 期望了**不存在的商品** `p_home_*`（数据集只有 beauty/digital/clothes/food 4 类，无 home）→ 必然 MISS；
- 「防晒霜」期望写成蜜粉、「蛋白粉」写成咖啡、「维生素」写成茶饮、「益生菌」写成能量饮料——张冠李戴。

→ 所以「低召回」至少一半是**测试集错误造成的假象**。

### 7.3 做了什么
1. **重修评测集**：期望 ID 全部基于真实商品的 `sub_category` 字段（权威标签），28 条覆盖 4 类目，剔除不存在 ID。
2. **加入跨模态检索**：新增 `RetrieverService.retrieveProductsMultiModal()`——
   `text→text`（CLIP 文本塔查文本库） + **`text→image`（同一个 CLIP 文本向量查图像库）**，两路 RRF 融合。
3. **参数调优**：扫描「文本权重/图像权重/候选池倍数」，取最优。
4. **接生产**：`ChatService` 两处检索调用从 `retrieveProductsByText` 换成 `retrieveProductsMultiModal`。

### 7.4 原理（关键认知）
Chinese-CLIP 是**图文对齐**模型，强项是**跨模态**匹配（image→image、test→image、image→text），
**不是 text→text 文本检索**。但原代码从头到尾只用了 `text→text`（CLIP 最弱的方向），
图像 collection 建好却从没被跨模态查询过——等于把一个多模态模型当纯文本模型用。

调参还证明：**图像通道权重越高越好（0.7 > 0.5 > 0.3）**，
即 CLIP 的**图像 embedding 对商品区分度远强于其文本塔**，图片才是这个模型的价值所在。

### 7.5 效果
| 指标 | 修正集基线(text-only) | 多模态(t=0.3/i=0.7/pool4) |
|------|:---:|:---:|
| Hit@1 | 53.57% | **85.71%** |
| Hit@3 | 67.86% | **96.43%** |
| Hit@5 | 71.43% | **100%** |
| Hit@10 | 89.29% | **100%** |
| MRR | 0.6337 | **0.9137** |

生产 `rag.top-k=3`，Hit@3=96.43% → Agent 上下文几乎每次都有相关商品（原仅 68%）。
**零索引重建、零新模型**，纯靠正确使用已有的多模态模型。

### 7.6 相关文件
- `RetrieverService.java`：`retrieveProductsMultiModal()`、权重常量 `MM_TEXT_WEIGHT=0.3`/`MM_IMAGE_WEIGHT=0.7`/`MM_POOL_MULT=4`

## 8. 数据库 Schema 治理（Flyway 版本化迁移）

> 对应 Bug 记录 **BUG-003**。

### 8.1 问题：Schema 漂移
仓库里描述的表结构 ≠ 线上真实结构：
- `users` 表只在文档里，**没有任何可执行 DDL**；
- `cart_items` 线上比 `init.sql` 多 3 列（`sku_id`/`sku_label`/`user_id`，手工 `ALTER` 加的）；
- 建表逻辑散落在 4 处：`data/init.sql`（Day0-1 后未更新）+ 3 个 Repository 的 `@PostConstruct` + 文档 + 手工执行。

**后果**：新环境 clone 后跑不起来（不可复现），结构变更无审计、易冲突。

### 8.2 做了什么
1. **以线上为唯一真相**：`SHOW CREATE TABLE` 导出 10 张表真实结构 → `db/migration/V1__baseline.sql`（按外键依赖排序：`products` 最先）。
2. 引入 **Flyway**（`flyway-core` + `flyway-mysql`，版本由 Spring Boot 父 POM 管理）。
3. 配置 `baseline-on-migrate: true` + `baseline-version: 1`。
4. **删除 Java 建表**：`ConversationRepository.initTables`、`UserBehaviorRepository.initTables`、`OrderRepository.ensureTableExists` 及 `OrderController` 中的调用。
5. `data/init.sql` 瘦身为"仅建库"。

### 8.3 原理：baseline 如何"不动数据"接入
- 已有数据的库**没有** `flyway_schema_history` → Flyway 判定为「非空且无历史」，执行 **baseline**：只建历史表，把现状**标记**为 V1，**不执行 V1**（数据/结构原样保留）。
- 全新空库 → 无历史 → **直接执行 V1** 建出全表。
- 之后任何变更一律新增 `V2__xxx.sql`，Flyway 按版本递增执行；**禁止手工 ALTER 线上**。

### 8.4 验证
- **线上库**：日志 `Successfully baselined schema with version: 1` → `Schema is up to date. No migration necessary.`；`flyway_schema_history` = `(1,'1','baseline',BASELINE,1)`；**数据无损**（products=100 / users=11 / conversations=29 / messages=168 / orders=3 / cart_items=12 / user_behaviors=173）。
- **接口冒烟**：商品列表 / 加购 / 购物车 / SSE 对话均通过。
- **待补**：干净空库实跑 V1（当前 `rag_agent` 账号无 `CREATE DATABASE` 权限）。

### 8.5 相关文件
- 新增：`server/src/main/resources/db/migration/V1__baseline.sql`
- 修改：`pom.xml`、`application.yml(.example)`、`data/init.sql`
- 删除：`ConversationRepository.initTables` / `UserBehaviorRepository.initTables` / `OrderRepository.ensureTableExists`

### 8.6 后续规范
- 结构变更 → 新增 `V{n}__描述.sql`，code review 后合入。
- `init.sql` 不再承载表结构，只负责建库。
