# 管理后台 + 性能监控 · 技术选型

> 状态：**已评审通过**（2026-09-26）　|　分三期落地：P0 → P1 → P2
> 关联：`docs/开发复盘.md`、`docs/Bug记录.md`

## 0. 目标与边界

- **管理后台**：可视化查看 用户 / 会话 / 订单 / 行为 + 活跃量看板。
- **性能监控**：系统指标（JVM/HTTP/连接池）+ 本项目特有**业务指标**（RAG 检索耗时、LLM 首 token 延迟、SSE 连接数、判官分数）。
- **边界**：只读为主（不做用户 CRUD / 复杂 RBAC），先落地再迭代。

## 1. 总体架构

```
admin/ (独立 Vite 应用)  ──/api/admin/**──►  Spring Boot
                                                  │
                        ┌─────────────────────────┼──────────────────────────┐
                        ▼                         ▼                          ▼
                   MySQL(现有表)          Actuator /actuator/prometheus   MeterRegistry 埋点
                                                                            │
                                            Prometheus ──scrape──► Grafana (看板/告警)
```

## 2. 后端（Spring Boot 侧）

| 项 | 选型 | 理由 |
|---|---|---|
| 数据访问 | **沿用 JdbcTemplate** | 与现有代码一致，不引 JPA 造成割裂 |
| 权限 | `users.role`（Flyway 迁移）+ JWT 加 `role` claim + `HandlerInterceptor` 拦 `/api/admin/**` | 复用现有 JWT，改动最小 |
| 接口 | `AdminController`（`/api/admin/**`，只读） | 分页查询 + SQL 聚合 |
| 可观测性 | **spring-boot-starter-actuator** + **micrometer-registry-prometheus** | 业界标准，零手搓 |

**自定义业务指标**（`MeterRegistry` 注入 `RetrieverService` / `ChatService`）：

| 指标 | 类型 | 说明 |
|---|---|---|
| `rag.retrieval.duration` | Timer | RAG 检索耗时 + 命中数 |
| `llm.first_token.duration` | Timer | 首 token 延迟 |
| `llm.total.duration` | Timer | 整轮耗时 |
| `sse.active.connections` | Gauge | 活跃 SSE 连接数 |
| `cart.tool.success.rate` | Counter | 加购/删车成功率 |
| `judge.score` | Gauge | LLM-as-Judge 分数趋势 |

## 3. 前端（管理后台）

**形态：独立 `admin/` 应用**（不与 `web/` 混）。理由：受众不同、可独立部署、不把后台代码打进顾客端包。

| 项 | 选型 | 理由 |
|---|---|---|
| 构建 | Vite + React + TS | 与现有栈一致 |
| 组件库 | **Ant Design 5** | 后台重度依赖 Table/Form/DatePicker，开箱即用 |
| 图表 | **ECharts**（echarts-for-react） | 活跃量趋势 / 分布图 |
| 请求 | axios（+ TanStack Query 可选） | 缓存/重试 |
| 路由 | react-router | 一致 |

## 4. 监控栈（Docker）✅ 已定

| 组件 | 选型 | 部署 |
|---|---|---|
| 指标暴露 | Actuator `/actuator/prometheus` | 后端自带 |
| 采集 | **Prometheus** | Docker |
| 看板/告警 | **Grafana** | Docker |

- 一份 `docker-compose.monitoring.yml` 起 Prometheus + Grafana（含预置 dashboard）。
- 现成面板：JVM 内存/GC、HTTP QPS/延迟、HikariCP 连接池、Tomcat 线程。
- 自定义面板：第 2 节那批业务指标。
- **学习目标**：熟悉 Docker 镜像/容器/卷/网络、compose 编排、服务发现与抓取配置。

## 5. 数据模型变更（走 Flyway，禁止手工改）

| 迁移 | 内容 |
|---|---|
| `V2__add_user_role.sql` | `users` 加 `role VARCHAR(20) NOT NULL DEFAULT 'USER'` |
| `V3__daily_metrics.sql`（可选，当前量级不必） | 活跃量预聚合快照表 |

**活跃量**先直接聚合现有表（零新表）：DAU/新增用户 ← `users`/`user_behaviors`；对话/消息 ← `conversations`/`messages`；订单/GMV ← `orders`。

## 6. 部署

- 后台前端：`npm run build` → 静态托管（nginx 或后端 `/admin` 静态目录）。
- 监控：`docker-compose.monitoring.yml`（Prometheus + Grafana）。
- 敏感配置：`application.yml`（已 gitignore）+ compose `.env`（gitignore）。

## 7. 分期路线

| 期 | 内容 | 估时 |

## 8. 已定决策

1. 后台前端 = **独立 `admin/` 应用 + Ant Design**。
2. 监控 = **Prometheus + Grafana（Docker）**。
3. 后台 = **只读为主**（暂不做用户禁用/改角色等写操作）。
4. 监控部署位置：**先本机 Docker**（后端在本机，最省事）；compose 保持可迁移到远程 `159.75.105.25`。
