# RAG 电商导购 Agent — 演示方案

## 一、项目功能总览

### 1.1 核心 RAG 能力

| 功能 | 说明 | 对应模块 |
|------|------|----------|
| 多模态 Embedding | 文本 + 图片向量化，存入 ChromaDB 双 Collection | EmbeddingService、KnowledgeIndexer |
| 语义检索 | 文本查询 → 向量相似度 → Top-K 商品召回 | RetrieverService |
| RAG 生成 | 检索结果注入 System Prompt → LLM 生成推荐回复 | ChatService |
| 流式输出 | SSE 协议逐字推送，前端实时显示 | ChatController、SseClient |
| 防幻觉 | sanitizeProductTags + 编辑距离修正，确保只推荐真实商品 | ChatService |
| 查询预处理 | 去除口语噪音词（"帮我"、"一下"等），提升检索准确率 | ChatService |
| 多轮追问增强 | 短追问自动拼接历史关键词，避免检索为空 | ChatService |

### 1.2 对话驱动购物

| 功能 | 说明 |
|------|------|
| 智能追问 | 单一品类（"推荐跑鞋"）必须追问，双维度才推荐 |
| 编号选规格 | LLM 展示规格编号列表，用户回复数字即可选择 |
| 对话加购 | 用户说"加入购物车" → LLM 问规格 → 确认后生成 [ADD_TO_CART] 标签 |
| 规格标签传递 | SSE 事件携带 skuLabel，后端反查 skuId 正确入库 |
| 购物车去重 | 同规格商品自动合并数量，手动加购和 Agent 加购结果一致 |

### 1.3 商品展示

| 功能 | 说明 |
|------|------|
| 商品图片 | 后端 Base64 编码注入 API，前端全链路展示 |
| 图片查看器 | 商品详情页点击图片弹出全屏大图 |
| 规格选择弹窗 | 底部弹窗展示商品图片 + 规格选项 + 数量选择 |
| FlowLayout | 规格标签自动换行，适配多种规格场景 |
| 商品详情页 | 规格选择 + 用户评价 + FAQ + 加购/购买按钮 |

### 1.4 购物车与支付

| 功能 | 说明 |
|------|------|
| 购物车管理 | 增删改查、数量调整、全选/单选、滑动删除 |
| 购物车跳转 | 点击购物车商品区域跳转商品详情页 |
| 虚拟支付 | 选中商品 → 确认订单 → 模拟支付成功 |
| 对话清空购物车 | 用户说"清空购物车" → [CLEAR_CART] 标签触发 |

### 1.5 用户系统

| 功能 | 说明 |
|------|------|
| 注册/登录 | JWT 认证，BCrypt 密码加密 |
| 欢迎页 | 首次进入展示欢迎页，引导登录或直接体验 |
| 对话持久化 | 登录用户的对话历史保存到 MySQL |
| 历史会话 | 查看历史对话列表，点击恢复对话上下文 |
| 购物车身份绑定 | 登录后购物车从 sessionId 迁移到 userId |

### 1.6 个性化推荐

| 功能 | 说明 |
|------|------|
| V1 关键词推荐 | 基于历史对话提取品类关键词 |
| V2 语义推荐 | 历史消息 Embedding 检索相似商品 |
| V3 行为加权 | 浏览/加购/购买行为加权 + 时间衰减 |
| 降级链 | V3 → V2 → V1，确保推荐始终可用 |
| 已购过滤 | 推荐结果排除已购买商品 |

### 1.7 Android 客户端

| 功能 | 说明 |
|------|------|
| 聊天界面 | 气泡对话、商品卡片、加载动画 |
| 推荐卡片 | 首页横向滑动个性化推荐 |
| 建议词条 | 输入框上方展示常见问题，点击直接发送 |
| 购物车页面 | 商品列表、数量调整、勾选结算 |
| 商品详情页 | 大图 + 规格 + 评价 + FAQ |

## 二、演示流程（建议 8 分钟）

### 开场（30秒）

> "我们的项目是基于 RAG 的多模态电商智能导购 Agent。用户通过自然语言对话，系统检索商品库，LLM 生成个性化推荐，支持对话加购、规格选择、购物车管理等完整购物流程。"

### 第一幕：RAG 检索与对话（2分钟）

**演示重点**：展示 RAG 核心能力

1. **基础检索推荐**
   - 输入："推荐一款保湿面霜"
   - 展示：流式输出 + 商品卡片 + 图片显示
   - 说明："系统从 100 个商品中检索最相关的 3 个，注入 Prompt 让 LLM 推荐"

2. **追问增强**
   - 追问："有没有更便宜的"
   - 展示：自动拼接历史上下文，推荐更低价商品
   - 说明："短追问会自动拼接上一轮关键词，避免检索为空"

3. **智能追问**
   - 输入："推荐跑鞋"
   - 展示：LLM 追问品牌、价位、场景
   - 说明："单一品类会追问，两个以上维度才直接推荐"

### 第二幕：对话驱动购物（2分钟）

**演示重点**：展示 Agent 的购物能力

4. **对话加购流程**
   - 输入："推荐一双 Nike 跑鞋"
   - LLM 推荐商品 + 展示规格编号
   - 输入："2"（选择规格）
   - LLM 确认并加购

5. **规格一致性**
   - 打开购物车 → 展示规格标签正确显示
   - 说明："Agent 加购和手动加购的规格格式统一，购物车自动去重合并"

### 第三幕：商品详情与手动购物（1分30秒）

**演示重点**：展示完整的手动购物体验

6. **商品详情页**
   - 点击商品卡片 → 跳转详情页
   - 展示：大图（点击可放大）+ 规格选择 + 评价 + FAQ

7. **手动加购**
   - 点击"加入购物车" → 规格弹窗
   - 选择规格和数量 → 确认

8. **购物车管理**
   - 调整数量、勾选商品、查看总价

### 第四幕：个性化推荐（1分钟）

**演示重点**：展示推荐系统

9. **推荐卡片**
   - 首页展示个性化推荐（基于历史行为）
   - 说明："V3 行为加权推荐，已购商品自动过滤"

10. **历史对话**
    - 点击历史会话 → 恢复对话上下文
    - 说明："登录用户的对话持久化到 MySQL"

### 第五幕：技术亮点（1分30秒）

**演示重点**：展示技术深度（可结合代码或架构图）

11. **防幻觉机制**
    - 展示 sanitizeProductTags + 编辑距离修正
    - 说明："LLM 编造的商品 ID 会被自动修正或移除"

12. **多模态 Embedding**
    - 展示 ChromaDB 双 Collection（文本 + 图片）
    - 说明："文本和图片分别向量化，RRF 融合排序"

13. **SSE 流式架构**
    - 展示实时逐字输出的用户体验
    - 说明："基于 LangChain4j + Spring SseEmitter 的流式对话"

### 收尾（30秒）

> "总结一下，我们的核心能力是：RAG 检索增强生成 → 对话驱动购物 → 个性化推荐。技术栈是 Java Spring Boot + LangChain4j + ChromaDB + 豆包大模型，Android 客户端通过 SSE 协议实时展示。"

## 三、演示脚本（具体话术）

### 场景一：完整购物流程

```
用户：推荐一款 200 元以内的蓝牙耳机

Agent：这款华为 FreeBuds SE 2 性价比很高 [PRODUCT:p_digital_018]，
       续航 40 小时，支持主动降噪，售价 ¥199，非常符合您的预算~

用户：加入购物车

Agent：这款耳机有以下规格可选：
       1. 标准版 / 典雅黑
       2. 标准版 / 冰霜银
       请问您想要哪个？回复编号即可~

用户：1

Agent：好的，已为您将典雅黑版本加入购物车 [ADD_TO_CART:p_digital_018:1:标准版 / 典雅黑]
```

### 场景二：智能追问 vs 直接推荐

```
用户：推荐护肤品
Agent：请问您想要什么类型的护肤品呢？我们有精华、面霜、洁面等品类，
       您也可以告诉我您的肤质和预算~
       ↑ 单一品类，追问

用户：油皮用的洗面奶
Agent：这款芙丽芳丝洗面奶非常适合油皮... [PRODUCT:p_beauty_011]
       ↑ 品类+肤质，直接推荐
```

### 场景三：多轮追问

```
用户：推荐保湿面霜
Agent：推荐薇诺娜面霜 [PRODUCT:p_beauty_007]...

用户：有没有更便宜的
Agent：这款 89 元的面霜性价比很高... [PRODUCT:p_beauty_012]
       ↑ query 增强：自动拼接 "保湿面霜 更便宜的"
```

## 四、演示注意事项

1. **提前准备**：确保后端已启动、数据库连接正常、ChromaDB 有数据
2. **网络稳定**：豆包 API 需要网络，确保代理配置正确
3. **清除缓存**：演示前清除购物车和对话历史，避免脏数据
4. **备用方案**：如果 LLM 响应慢，可以提前准备好截图/录屏
5. **节奏控制**：每个场景控制在 1-2 分钟，重点展示效果而非代码
